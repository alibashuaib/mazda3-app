<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anon/browser to PostgREST | Public anon key, any origin, can insert into app_errors directly |
| authenticated non-admin to app_errors | Signed-in user must not read or resolve other rows |
| CI runner to Supabase local stack | CI loads schema and runs tests with a throwaway DB |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Denial of service | app_errors insert flood via anon key | mitigate | BEFORE INSERT trigger refuses anon/authenticated inserts once 500 rows exist in the last hour; length CHECKs; client throttle in plan 01-05 |
| T-01-02 | Information disclosure | anon or non-admin reads error rows | mitigate | revoke all, then column-only grants; select policy uses is_admin(); SQL test cases 2 and 7 |
| T-01-03 | Tampering | client forges user_id or group_key | mitigate | user_id and group_key are not granted to clients and are overwritten by the trigger |
| T-01-04 | Tampering | policy regression (anon select re-granted) | mitigate | supabase/tests/app-errors-rls.sql in rls CI job with ON_ERROR_STOP; rls-coverage.test.js static check |
| T-01-05 | Information disclosure | error rows carry vehicle data | mitigate | table has no column for vehicle or record payload (D-03); enforced again in plan 01-05 and 01-09 |
| T-01-06 | Elevation of privilege | SECURITY DEFINER trigger misused | accept | Trigger body only reads counts and sets NEW fields; search_path pinned to public |
</threat_model>
